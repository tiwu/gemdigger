# Plan - Circular Dependencies and Build Output Corrupted Content Fix

Resolved the issue where running `npm run preview` loaded the app with only text and no styling, along with browser failed fetches for our script showing `NS_ERROR_CORRUPTED_CONTENT`.

## Overview
Vite's compiler produced a warning because `/src/js/leaderboard.js` was being dynamically imported by `/src/js/main.js` while also being statically imported at the top of the file:
```
(!) /home/twuytens/work/gemdigger/src/js/leaderboard.js is dynamically imported by /home/twuytens/work/gemdigger/src/js/main.js, /home/twuytens/work/gemdigger/src/js/main.js but also statically imported by /home/twuytens/work/gemdigger/src/js/main.js, dynamic import will not move module into another chunk.
```
This duplicate import pattern caused Rollup's chunk generation to produce a corrupt or invalid chunk reference mapping inside the bundled production output (`index.js`). Some browsers (especially Firefox) threw `NS_ERROR_CORRUPTED_CONTENT` because of invalid module bindings or headers mismatch when attempting to fetch the compiled assets under `npm run preview`.

## Key Changes
- **src/js/main.js**: Removed the static top-level imports of functions from `./leaderboard.js` (`getLeaderboard`, `saveLeaderboardEntry`, `updateLeaderboardEntryName`, `renderLeaderboard`, and `LB_NAME_KEY`). Replaced them with fully asynchronous dynamic `import()` calls at the exact local scopes where they are needed.
- **vite.config.js**: Left build properties clean to let Rollup properly split `leaderboard.js` into its own chunk during building.
